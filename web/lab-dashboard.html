▶ Loading a real database export

The interface reads a single global object, window.LAB_DATA, with one array per table. To use live data, export the tables to JSON (server-side) and replace the generated dataset — everything else re-renders automatically.

A one-shot export from PostgreSQL:

-- run per table, e.g. subjects:
\copy (SELECT json_agg(t) FROM lab.subject t) TO 'subject.json'
-- events joined with their active-version flag, artifacts, event_input, sessions, verifications ...

Then set, before the app script runs:

window.LAB_DATA = {
  people:[], probes:[], pipelines:[], storageRoots:[], species:[],
  projects:[ /* {project_id,name,description,started_on,is_active,created_by} */ ],
  projectMembers:[ /* {project_id, person_id, role} */ ],
  projectArtifacts:[ /* {project_artifact_id,project_id,title,kind,content_type,
                        uri,storage_root_id,relative_path} */ ],
  subjects:[ /* {subject_id, project_id, species_code, ...} */ ], sessions:[],
  events:[ /* {event_id,event_type,subject_id,session_id,occurred_at,
               recorded_at,recorded_by,supersedes,notes,detail:{...}} */ ],
  artifacts:[ /* {artifact_id,produced_by_event_id,storage_root_id,relative_path,
                 checksum,size_bytes,role,format,subject_id,session_id,supersedes,
                 verification:{status,verified_at}} */ ],
  eventInputs:[ /* {event_id, artifact_id, role} */ ]
};

Field names mirror the schema columns. detail holds the class-table-inheritance columns for that event type (e.g. recording_event.sample_rate_hz). Superseded rows are detected via the supersedes links, exactly like the event_active / artifact_active views.
