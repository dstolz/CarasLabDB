▶ How the live dashboard works

This page is served by web/live/server.py. On load it fetches /api/data, which runs web/live/lab_data.sql against the live PostgreSQL database and returns every table as one JSON object (the same window.LAB_DATA shape the offline demo builds synthetically). The rendering, filtering and drill-down code is identical to the offline demo.

Full history is returned — superseded rows included — and active vs. superseded state is derived client-side from the supersedes links, exactly like the lab.event_active / lab.artifact_active views. Tags work the same way: the vocabulary (tagNamespaces, tags) and the whole append-only tag log (tagAssignments) are loaded, and each row's current tags are derived in the browser like lab.tag_current. Type tags such as stage:raw -qc:fail topic:* in the Tags filter (# focuses it). User-defined variables come the same way: the definitions (variables) and the whole value log (variableValues, each value as the text the database stored), from which the current values are derived like lab.variable_current. Retracted events and files (lab.retraction) count as not active, as in the *_active views. The Integrity panel summarises lab.fn_check_integrity(); the server recomputes it every few minutes, not on every load, because it is as expensive as the rest of the export. The address bar always holds the tab, the filters and the open record, so a record can be linked from a notebook. Hit ↻ Refresh to re-query the database.

Run it from the repo root (with the schema applied to database lab):

PGDATABASE=lab python web/live/server.py --port 8778
# then open http://127.0.0.1:8778/

Connection settings come from the standard libpq environment variables (PGHOST, PGPORT, PGDATABASE, PGUSER, PGPASSWORD). Data access uses psycopg/psycopg2 if installed, otherwise the psql CLI. See web/live/README.md for details.
